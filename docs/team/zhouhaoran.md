## 自我反思

**做得还可以的地方。** 我没有拿到草稿就直接排版，而是先对照 `docs/00-assignment-mapping.md` 把课程要求逐条核对了一遍。这一步在排版之前查出了三类问题：正文仍沿用重跑前的数字（36 runs、APFD 基线 0.659、“文件级开销低于 20 %”），而图已经按 PR #13 冻结后的 48 runs 结果重画（基线 0.521、自托管开销 28.28 %，已超过 20 % 阈值，RQ2 的判定必须改写）；全文没有一处图表编号和正文引用，八张图里还有两张没用上；十五条参考文献在正文中一次都没有被引用。如果先进排版，这些问题会被版式盖住，留到最后才暴露。

**低估的地方。** 我低估了报告对上游的依赖：评测数字直到 PR #13 合并才冻结，六人简介当时分散在四个未合并的 PR 里，而工时在仓库中长期没有任何记录来源——`weekly-evidence.md` 不记工时，`burndown.csv` 只有故事点且实际值只填到第 5 周；直到 11/26 深夜组长才在 `docs/process/evidence-ownership.md` 给出一版提议值，按该文件的要求仍需六人各自确认。我的进度实际是被合并顺序卡住的，不是被排版工作量卡住的。我也低估了一次评测重跑的返工面：它会牵动摘要、§1.4、§6、§7、§8 十几处数字，而不是改一个表格。

**如果重做一次。** 我会在 Sprint 2 就设一个“数字冻结 → 报告同步”的检查点，而不是等到 Sprint 3 才发现正文与图不一致；会在写作规范里就要求图表编号和正文引用，让它成为草稿的一部分而不是事后补的格式活；会更早在群里固定一个工时填报格式并每周收一次，让贡献表从一开始就有可追溯的依据，而不是最后由组长反推一版提议值。
