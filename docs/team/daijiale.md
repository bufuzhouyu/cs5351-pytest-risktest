## Self-reflection

- **最满意的交付**：`tests/test_selector_extra.py` 用 19 个测试函数收集到 22 个用例（其中一个对四种选择策略做了参数化），把完整套件从 99 passed 推到 121 passed；`docs/process/test-report.md` 里写的是实际跑出来的命令和数字，队友照着命令能复现。
- **遇到的具体问题**：第一次测覆盖率只有 62%，`cli.py` 和 `plugin.py` 显示 0%，我起初以为这两个模块没被测到。查过之后才明白它们是被 `test_cli.py` 和 `test_plugin_integration.py` 用 subprocess 拉起来的，coverage 统计不到子进程。我在报告里写清了这个原因，另外单独给出排除这两个文件后的 89.6%，没有直接把数字换成好看的那个。
- **一个实实在在的错误**：`docs/process/weekly-evidence.md` 里第 5 周的日期我先填成了 2026-11-21，后来对照周次才确认应当是 2026-10-05，只好单独开 PR #20 修正。教训是表里的日期要回查计划再填，不能照着提交当天的日期写。
- **下次可以改进的做法**：动手写断言之前先把每个测试要锁哪一条约定写下来，避免多个用例测同一件事；遇到红灯先判断是实现有 bug 还是用例写错，再决定要不要提 Issue，而不是顺手去改 `src/`（这次 `src/` 一行没动，也没发现缺陷）。
